### [Firewalling the AI Era: Why the Network Still Decides](https://blogs.cisco.com/security/firewalling-the-ai-era-why-the-network-still-decides)

### [PHP2Shell: How Cisco Helps Customers Respond to AI-Accelerated Threats](https://blogs.cisco.com/security/php2shell-how-cisco-helps-customers-respond-to-ai-accelerated-threats/)
- **概要**: AIが加速する脆弱性発見と対応時間の短縮に対し、CiscoはPHP2Shell脆弱性への対応事例を提示。Cisco Secure FirewallのSnortML機能は、Day-zeroで新たなエクスプロイト試行を検知・ブロックし、顧客は公開前から保護されていた。
- **プロダクト名**: Cisco Firewall, SnortML
- **バージョン**: ソフトウェア 10.1

### [Defenders need more time to patch with the influx of patching hitting operations](https://blogs.cisco.com/security/defenders-need-more-time-to-patch-with-the-influx-of-patching-hitting-operations/)
- **概要**: Frontier AIなどによる脆弱性発見が加速する中、パッチ適用に要する平均43日という期間が問題となっている。CiscoはLive Protect（仮想パッチ）機能を提供し、Talosが作成したSnortルールをSecure Firewallで適用することで、脆弱なホストに触れずにエクスプロイト試行をブロックし、パッチ適用までの時間稼ぎを支援する。
- **プロダクト名**: Secure Firewall, Live Protect, Snort, Secure Workload, FMC, Firepower Recommendations

### [Cisco Rethinks Privileged Infrastructure Access](https://blogs.cisco.com/security/cisco-rethinks-privileged-infrastructure-access/)
- **概要**: AIの進歩により高度な攻撃が容易になり、従来の特権アクセス管理の前提が崩れている。CiscoはTeleportとの提携を通じて「Infrastructure Identity」という概念を導入し、人、マシン、AIエージェントのインフラストラクチャへの特権アクセスを、アイデンティティ、アクセス権限、行動履歴を結びつけることで再構築している。

### [Unified Defense from Endpoint to Cloud: Real-Time Protection with Cisco Security, Splunk, and SentinelOne](https://blogs.cisco.com/security/unified-defense-from-endpoint-to-cloud/)
- **概要**: クラウド環境における迅速な変化が攻撃者に悪用される中、Silo化されたセキュリティツールでは不十分。Cisco SecurityとSplunk、SentinelOne Cloud Workload Protection (CWP) を統合することで、コンテナ、Kubernetes、VM、サーバーレスワークロードに対する自律的かつリアルタイムな脅威検知と対応を提供し、統合防御を実現する。
- **プロダクト名**: Cisco Security, Splunk, SentinelOne Cloud Workload Protection (CWP)

### [Cryptography Rarely Fails Because of the Math](https://blogs.cisco.com/security/last-mile-of-trust-post-quantum-cryptography-open-source/)
- **概要**: 暗号技術の失敗は、パッチ適用やサプライチェーンの課題、いわゆる「信頼のラストマイル」に起因することが多く、AIによる脆弱性発見の加速とポスト量子暗号（PQC）への移行がこのラストマイルに負荷をかけている。AIがバグ発見を加速する一方で、修正は人手に依存し、発見と修正のギャップが拡大している。

### [Always-On Assurance: How Cisco is Reimagining the Secure Development Lifecycle](https://blogs.cisco.com/security/always-on-assurance/)
- **概要**: 生成AIがセキュリティの規模を拡大する中、CiscoはオープンソースのFoundry Security SpecやAIエージェントを活用し、従来の属人的なセキュリティゲートから脱却。ソフトウェア開発ライフサイクル（CSDL）にセキュリティを直接組み込むことで、より普及し、プロアクティブで精密なセキュリティの実現を目指している。
- **プロダクト名**: Cisco Secure Development Lifecycle (CSDL), Foundry Security Spec (オープンソース)

### [Chasing AMMYY at Splunk .conf](https://blogs.cisco.com/security/conf26-agentic-soc-chasing-ammyy/)
- **概要**: Cisco Secure Firewall Threat Defense (FTD) のEncrypted Visibility Engine (EVE) が、Splunk .confネットワークで、遠隔操作ツールFlawed AMMYYを検知した事例を紹介。EVEは類似するアプリケーションをセッショングラニュラリティで識別し、HTTPとHTTPSの両方で可視性を提供する。
- **プロダクト名**: Cisco Secure Firewall Threat Defense (FTD), Encrypted Visibility Engine (EVE)

### [エッジでのエージェント運用：DefenseClaw で AI セキュリティガバナンスをフィジカル AI へと拡張](https://gblogs.cisco.com/jp/2026/11/agents-at-the-edge-extending-ai-security-governance-to-physical-ai-with-defenseclaw/)

### [Defenders need more time to patch with the influx of patching hitting operations](https://blogs.cisco.com/security/defenders-need-more-time-to-patch-with-the-influx-of-patching-hitting-operations/)
- **概要**: Frontier AIなどによる脆弱性発見が加速する中、パッチ適用に要する平均43日という期間が問題となっている。CiscoはLive Protect（仮想パッチ）機能を提供し、Talosが作成したSnortルールをSecure Firewallで適用することで、脆弱なホストに触れずにエクスプロイト試行をブロックし、パッチ適用までの時間稼ぎを支援する。

### [PHP コアの深刻な RCE 脆弱性について](https://gblogs.cisco.com/jp/2026/10/two-critical-rces-in-php-core/)
- **概要**: Cisco Talosは、PHPコアに存在する2件の深刻な認証不要RCE脆弱性「php2shell」（CVE-2026-109618, CVE-2026-109619、CVSS v4.0スコア9.2）を追跡している。PHP 5.4以降の全ビルドが影響を受け、Cisco顧客はSNORT®シグネチャ67359および67360で保護されている。
- **CVE**: CVE-2026-109618, CVE-2026-109619
- **CVSS**: v4.0 スコア 9.2
- **対象バージョン**: PHP 5.4 以降のすべてのビルド
- **対応**: 修正済みのリリースへのアップグレードを強く推奨。Cisco Talos Network Intrusion Prevention (SNORT®) シグネチャ 67359 および 67360 を適用。
